## Findings

1. **The filename `SPEC.md` meant three different document types.** `di/SPEC.md` is a genuine behavioural spec;
   `cli/SPEC.md` was a settled refactor decision + closed checklist; `tracking/SPEC.md` is a pointer into `spec/`. The
   shared name hid that they are different types — exactly the junk-drawer failure the type-based taxonomy exists to
   prevent.
2. **`tailwind-variants/RFC.md` was a settled decision, not an open RFC** — its header reads "accepted and implemented"
   (2025-09-14). The `RFC` name overstated its liveness.
3. **The agent guidance in `CLAUDE.md` described `di` as having "one design doc"**, never acknowledging that `SPEC.md`
   (the ~3,000-line behavioural contract) is itself a source-of-truth document alongside `ARCHITECTURE.md`.
4. **`tracking/SPEC.md` miscounted the spec set** — "six core documents … `spec-security` sits alongside", where
   [`spec/README.md`](../../packages/tracking/spec/README.md) lists `spec-security` as a seventh core document.

## Actions applied in this pass

- Renamed `packages/cli/SPEC.md` → **`DECISIONS.md`** (it self-identifies as decision history) and repointed the two
  links from [`cli/ARCHITECTURE.md`](../../packages/cli/ARCHITECTURE.md).
- Renamed `packages/tailwind-variants/RFC.md` → **`DECISIONS.md`** and repointed the link from
  [`tailwind-variants/ARCHITECTURE.md`](../../packages/tailwind-variants/ARCHITECTURE.md). This establishes a
  package-local `DECISIONS.md` convention that mirrors the repo-level [`decisions/`](../decisions/) type.
- Reworded the `packages/di` section of [`CLAUDE.md`](../../CLAUDE.md) to name `SPEC.md`, `ARCHITECTURE.md`, and
  `LEARNING.md` with their distinct roles.
- Corrected the spec count and added the missing `spec-security` bullet in
  [`tracking/SPEC.md`](../../packages/tracking/SPEC.md).

## Deliberately left unchanged

- **`cli/DECISIONS.md` §1 "a CLI tool with 3 commands"** — this sits in the section the document flags as pre-refactor
  context. `audit` was added after the refactor (it is absent from the §3 target layout), so "3 commands" is accurate
  for that historical snapshot; changing it to four would falsify the record.
- **`benchmarks/di-inversify/RESULTS.md` environment header pinning `@codefast/di 0.5.0-canary.8`** — the header is
  bound to the dated "last full re-measure" (2026-07-31). A newer full re-measure should add a new dated environment
  block rather than overwrite this one.
